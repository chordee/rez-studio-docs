# Rez 中央伺服器與全域配置規範

本文檔說明中央儲存庫規劃、基礎環境綁定（`rez-bind`）、Memcached 解析快取配置，以及全域共用的 `rezconfig.py` 生產設定標準。

---

## 一、基礎環境綁定（Bootstrap rez-bind）

> [!IMPORTANT]
> **執行本節前的前置條件**
>
> 1. 執行機台已依 [00-Rez安裝與導入順序](00-Rez安裝與導入順序.md) 安裝 Rez（`rez --version` 可正常執行）。
> 2. 中央 `rezconfig.py`（本篇第五節）已放置到位，且 `REZ_CONFIG_FILE` 指向它。
> 3. 執行帳號對 `packages/` 具有寫入權限（見本篇第二節 ACL）。
>
> 完整的導入先後順序請見 00 的「導入順序」表格。

在全新建立的 Rez 中央套件庫中，預設是完全空白的。若後續套件宣告了 `platform-windows` 或 `platform-linux` 等變體，Rez 會因找不到 `platform` 套件家族而拋出：
```text
PackageFamilyNotFoundError: package family not found: platform
```

> [!IMPORTANT]
> **`rez-bind` 一次僅能綁定一個套件**
>
> `rez-bind` 指令每次只接收一個套件名稱參數，若一次傳入多個名稱會噴出 `unrecognized arguments`。

因此在正式啟用中央儲存庫前，必須以具 `packages/` 寫入權限的 TD 帳號，分別在 Windows 機台與 Linux 機台執行以下指令發布基礎套件。依第二節 ACL，農場節點對 `packages/` 為唯讀，不能用來執行綁定：

```bash
# 在 Windows 機台上執行（逐一發布至中央庫；使用 UNC 路徑，理由見第二節掛載點說明）
rez-bind -i //nas/share/rez-system/packages platform
rez-bind -i //nas/share/rez-system/packages arch
rez-bind -i //nas/share/rez-system/packages os

# 在讀寫掛載 NAS 的 Linux TD 機台上執行（逐一發布至中央庫）
rez-bind -i /mnt/x/rez-system/packages platform
rez-bind -i /mnt/x/rez-system/packages arch
rez-bind -i /mnt/x/rez-system/packages os
```

綁定完成後，中央庫即具備 `platform-windows`、`platform-linux`、`arch-AMD64`、`arch-x86_64` 等原生系統套件定義。

## 二、中央儲存庫目錄結構與權限

全公司共用一套中央儲存路徑，在 Windows 與 Linux 工作站皆有明確的掛載點映射：

* **Windows 掛載點**：`X:\rez-system`（專案與一般瀏覽用；Rez 本身在 Windows 端一律以 UNC 路徑 `\\nas\share\rez-system` 存取，理由見 02 第一節）
* **Linux 掛載點**：`/mnt/x/rez-system`

### 1. 目錄樹規劃

```text
X:/rez-system/ (或 /mnt/x/rez-system/)
├── config/
│   └── rezconfig.py          # 全工作室中央基礎設定檔
├── installers/
│   └── rez-3.4.0.zip         # 官方 Rez Release Asset（離線安裝用，見 00）
└── packages/                 # 正式發布套件庫（Production packages）
    ├── platform/             # 由 rez-bind 產生之作業系統標籤
    ├── arch/                 # 由 rez-bind 產生之 CPU 架構標籤
    ├── os/                   # 由 rez-bind 產生之 OS 發行版本標籤
    ├── houdini/              # Houdini Wrapper 套件
    ├── maya/                 # Maya Wrapper 套件
    ├── nuke/                 # Nuke Wrapper 套件
    ├── htoa/                 # Arnold for Houdini (Payload 套件)
    ├── maya_usd/             # Maya-USD (Payload 套件)
    └── studio_pipeline/      # 自研工作室 Pipeline 工具包
```

### 2. ACL 檔案權限劃分

| 角色 / 機台 | `config/` 權限 | `packages/` 權限 | 目的 |
| :--- | :--- | :--- | :--- |
| **Artist 工作站** | 唯讀（Read-Only） | 唯讀（Read-Only） | 僅讀取設定與解析套件，防止意外修改 |
| **Render Farm 節點** | 唯讀（Read-Only） | 唯讀（Read-Only） | 高並發唯讀存取，避免競爭條件 |
| **Pipeline TD / Lead** | 讀寫（Read-Write） | 讀寫（Read-Write） | 執行 `rez-release` 發布正式套件 |
| **CI/CD 自動化機器** | 唯讀（Read-Only） | 讀寫（Read-Write） | 自動編譯與自動測試通過後統一發布 |

### 3. 農場 Worker 的 NAS 存取身分

上表的「Render Farm 節點」必須落實到 Deadline Worker 實際向 NAS 驗證的身分。Machine 環境變數只告訴 Rez 去哪裡找檔案，**不會**給予任何存取權；02 的 `-WorkerAccount` 也只授權本機目錄。

| Worker service 的登入身分 | NAS 上要授權的對象 |
| :--- | :--- |
| 網域服務帳號（例如 `STUDIO\svc-deadline`） | 該帳號，或包含它的群組 |
| gMSA（例如 `STUDIO\gmsa-deadline$`） | 該 gMSA，或包含它的群組 |
| LocalSystem | 各農場電腦的電腦帳號（`STUDIO\RENDER01$` 等）。LocalSystem 存取網路時以電腦帳號驗證；建議把農場電腦加入專用 AD 群組（例如 `STUDIO\rez-farm-nodes`）後授權該群組，不要直接授權 `Domain Computers` |
| 本機帳號（非網域） | 無法以網域身分存取 NAS，不應用於農場 Worker |

* **SMB share 權限與檔案系統 ACL 都要設定**：實際權限取兩者中較嚴格的一方，只設其中一層會導致存取被拒或權限過大。
* 上述身分對 `config/` 與 `packages/` 皆為唯讀。
* **Linux 農場**：NAS 存取身分由 `/mnt/x` 的掛載方式決定（NFS 的 uid/gid 對應，或 CIFS 掛載使用的帳號），須確認 Deadline unit 的執行帳號可讀取 `/mnt/x/rez-system`。

## 三、Rez 設定載入優先序與邊界說明

> [!WARNING]
> **中央設定並非最高權重**
>
> 在 Rez 的配置載入階層中，載入順序由低至高為：
> 1. Rez 核心內建之 `rezconfig.py`
> 2. `REZ_CONFIG_FILE` 環境變數所指向的檔案（即本中央設定檔）
> 3. 使用者家目錄下的 `~/.rezconfig` 或 `~/.rezconfig.py`
> 4. `REZ_*` 系列環境變數（最高優先權）
>
> 因此，算圖農場節點必須透過環境變數設定 `REZ_DISABLE_HOME_CONFIG=1`，確保節點不會被該機台 local 使用者的私人設定覆寫。

## 四、Memcached 伺服器整合與安全性

本模擬環境配置了一台專屬 Memcached 伺服器：
* **伺服器位址**：`192.168.0.221:11211`

### 1. 快取範疇與機制
- **Resolve Caching**：相同套件請求（如 `houdini-20.5.278 htoa-6.3.3.0`）解析成功後，將解算結果快取在記憶體中，後續相同請求直接命中，大幅減少磁碟遍歷。
- **Package Files & Listdir Caching**：快取套件庫的目錄清單與檔案狀態，顯著降低高並發下對 NAS 的 stat / read 負擔。
- **故障降級（Failover）**：Memcached 僅作為加速層。若伺服器離線或連線逾時，Rez 會自動回退至實體檔案系統進行解析，不會造成生產線中斷。

### 2. 網路安全防護
- Memcached 原生不提供身分驗證，**嚴禁**暴露至公網或非信任網段。
- 必須透過防火牆規則限制僅允許工作站內網與農場節點 IP 存取 `11211` 連接埠。

## 五、生產級 `rezconfig.py` 設定檔

放置於 `X:/rez-system/config/rezconfig.py`（Linux 位於 `/mnt/x/rez-system/config/rezconfig.py`）。

注意：檔案中的輔助變數使用底線前綴（例如 `_rez_root`），避免與 Rez 正式設定名稱衝突；Rez 會忽略不認識的鍵：

```python
# -*- coding: utf-8 -*-
"""
Studio Central Rez Configuration
檔案位置: X:/rez-system/config/rezconfig.py 或 /mnt/x/rez-system/config/rezconfig.py
"""
import os
import sys

# ==============================================================================
# 1. 套件搜尋與發布路徑
# ==============================================================================
# 底線前綴避免與 Rez 正式設定名稱衝突；Rez 會忽略不認識的鍵
_default_rez_root = "X:/rez-system" if sys.platform == "win32" else "/mnt/x/rez-system"
_rez_root = os.getenv("STUDIO_REZ_ROOT", _default_rez_root).rstrip("/\\").replace("\\", "/")

# 套件搜尋路徑：一般使用者只讀中央庫；TD 明確啟用開發模式時才加入本機庫
# 農場端仍固定附加 --no-local，作為第二層隔離防護
packages_path = (
    ["~/rez-client/packages"] if os.getenv("STUDIO_REZ_DEV") == "1" else []
) + [f"{_rez_root}/packages"]

# rez-build --install 預設安裝目標（TD 本機測試區）
local_packages_path = "~/rez-client/packages"

# rez-release 正式發布目標（明確指定中央庫，避免發布到預設本機路徑）
release_packages_path = f"{_rez_root}/packages"

# ==============================================================================
# 2. 本機套件快取目錄 (Package Cache)
# 僅在算圖農場節點（STUDIO_FARM_NODE=1）啟用，快取宣告了 cachable = True 的套件負載
# 工作站不啟用：多帳號共用的電腦上，可寫入的共用快取會讓任一帳號竄改其他帳號執行的外掛
# Linux 嚴禁使用重開機可能被清空的 /tmp，改用 /var/cache/rez
# ==============================================================================
cache_packages_path = (
    ("C:/rez-cache" if sys.platform == "win32" else "/var/cache/rez")
    if os.getenv("STUDIO_FARM_NODE") == "1" else None
)

# ==============================================================================
# 3. Memcached 解析快取伺服器配置 (標準欄位)
# ==============================================================================
memcached_uri = ["192.168.0.221:11211"]

# 啟用解析結果快取
resolve_caching = True

# 啟用套件清單與檔案元數據快取
cache_package_files = True
cache_listdir = True

# 壓縮閥值（大於 1024 Bytes 的解析結果先壓縮後再進 memcached）
memcached_resolve_min_compress_len = 1024
```

未設定 `STUDIO_REZ_ROOT` 時，Windows 與 Linux 分別沿用 `X:/rez-system` 與 `/mnt/x/rez-system`。Deadline service 看不到 Windows 映射磁碟時，請在 Machine 層級設定 `STUDIO_REZ_ROOT=//nas/share/rez-system`；`packages_path` 與 `release_packages_path` 會共同使用此根目錄。

> [!NOTE]
> **解析逾時時間**
>
> Rez 設定檔中並無 `resolve_timeout` 欄位。若需要在 CLI 或腳本中限制解析耗時，請使用 `rez-env --time-limit <SECONDS>` 參數。

## 六、設定驗證

在已配置好環境的機器上執行：

```bash
# 檢查單一設定欄位（rez-config 一次只接收一個欄位參數）
rez-config packages_path
rez-config release_packages_path

# 或列出所有生效的設定檔來源清單
rez-config --source-list

# 檢查 Memcached 伺服器狀態與快取命中統計
rez-memcache --stats
```
