# Rez 中央伺服器與全域配置規範

本文檔說明中央儲存庫規劃、基礎環境綁定（`rez-bind`）、Memcached 解析快取配置，以及全域共用的 `rezconfig.py` 生產設定標準。

---

## 一、基礎環境綁定（Bootstrap rez-bind）

在全新建立的 Rez 中央套件庫中，預設是完全空白的。若後續套件宣告了 `platform-windows` 或 `platform-linux` 等變體，Rez 會因找不到 `platform` 套件家族而拋出：
```text
PackageFamilyNotFoundError: package family not found: platform
```

因此在正式啟用中央儲存庫前，必須在 Windows 工作站與 Linux 農場節點各執行一次基礎綁定：

```bash
# 在 Windows 機台上執行（發布至中央庫）
rez-bind -i X:/rez-system/packages platform arch os

# 在 Linux 機台上執行（發布至中央庫）
rez-bind -i /mnt/x/rez-system/packages platform arch os
```

綁定後，中央庫即具備 `platform-windows`、`platform-linux`、`arch-AMD64`、`arch-x86_64` 等原生系統套件定義。

---

## 二、中央儲存庫目錄結構與權限

全公司共用一套中央儲存路徑，在 Windows 與 Linux 工作站皆有明確的掛載點映射：

* **Windows 掛載點**：`X:\rez-system`
* **Linux 掛載點**：`/mnt/x/rez-system`

### 1. 目錄樹規劃

```text
X:/rez-system/ (或 /mnt/x/rez-system/)
├── config/
│   └── rezconfig.py          # 全工作室中央基礎設定檔
└── packages/                 # 正式發布套件庫（Production packages）
    ├── platform/             # 由 rez-bind 產生之作業系統標籤
    ├── arch/                 # 由 rez-bind 產生之 CPU 架構標籤
    ├── os/                   # 由 rez-bind 產生之 OS 發行版本標籤
    ├── houdini/              # Houdini Wrapper 套件
    ├── maya/                 # Maya Wrapper 套件
    ├── nuke/                 # Nuke Wrapper 套件
    ├── htoa/                 # Arnold for Houdini (Payload 套件)
    ├── maya_usd/             # Maya-USD (Payload 套件)
    └── studio_pipeline/      # 自研工作室 Pipeline 工具包
```

### 2. ACL 檔案權限劃分

| 角色 / 機台 | `config/` 權限 | `packages/` 權限 | 目的 |
| :--- | :--- | :--- | :--- |
| **Artist 工作站** | 唯讀（Read-Only） | 唯讀（Read-Only） | 僅讀取設定與解析套件，防止意外修改 |
| **Render Farm 節點** | 唯讀（Read-Only） | 唯讀（Read-Only） | 高並發唯讀存取，避免競爭條件 |
| **Pipeline TD / Lead** | 讀寫（Read-Write） | 讀寫（Read-Write） | 執行 `rez-release` 發布正式套件 |
| **CI/CD 自動化機器** | 唯讀（Read-Only） | 讀寫（Read-Write） | 自動編譯與自動測試通過後統一發布 |

## 三、Rez 設定載入優先序與邊界說明

> [!warning] 中央設定並非最高權重
> 在 Rez 的配置載入階層中，載入順序由低至高為：
> 1. Rez 核心內建之 `rezconfig.py`
> 2. `REZ_CONFIG_FILE` 環境變數所指向的檔案（即本中央設定檔）
> 3. 使用者家目錄下的 `~/.rezconfig` 或 `~/.rezconfig.py`
> 4. `REZ_*` 系列環境變數（最高優先權）
>
> 因此，算圖農場節點必須透過環境變數設定 `REZ_DISABLE_HOME_CONFIG=1`，確保節點不會被該機台 local 使用者的私人設定覆寫。

## 四、Memcached 伺服器整合與安全性

本模擬環境配置了一台專屬 Memcached 伺服器：
* **伺服器位址**：`192.168.0.221:11211`

### 1. 快取範疇與機制
- **Resolve Caching**：相同套件請求（如 `houdini-20.5.278 htoa-6.3.3.0`）解析成功後，將解算結果快取在記憶體中，後續相同請求直接命中，大幅減少磁碟遍歷。
- **Package Files & Listdir Caching**：快取套件庫的目錄清單與檔案狀態，顯著降低高並發下對 NAS 的 stat / read 負擔。
- **故障降級（Failover）**：Memcached 僅作為加速層。若伺服器離線或連線逾時，Rez 會自動回退至實體檔案系統進行解析，不會造成生產線中斷。

### 2. 網路安全防護
- Memcached 原生不提供身分驗證，**嚴禁**暴露至公網或非信任網段。
- 必須透過防火牆規則限制僅允許工作站內網與農場節點 IP 存取 `11211` 連接埠。

## 五、生產級 `rezconfig.py` 設定檔

放置於 `X:/rez-system/config/rezconfig.py`（Linux 位於 `/mnt/x/rez-system/config/rezconfig.py`）。

注意：為避免輔助變數洩漏進 Rez 設定字典命名空間，採用乾淨的直接表達式：

```python
# -*- coding: utf-8 -*-
"""
Studio Central Rez Configuration
檔案位置: X:/rez-system/config/rezconfig.py 或 /mnt/x/rez-system/config/rezconfig.py
"""
import sys

# ==============================================================================
# 1. 套件搜尋與發布路徑
# ==============================================================================
# 套件搜尋路徑（依序搜尋：本機開發區 -> 中央正式庫）
# 注意：農場端排程器執行時應主動附加 --no-local 參數以排除本機開發區
packages_path = [
    "~/rez-client/packages",
    "X:/rez-system/packages" if sys.platform == "win32" else "/mnt/x/rez-system/packages"
]

# rez-build --install 預設安裝目標（TD 本機測試區）
local_packages_path = "~/rez-client/packages"

# rez-release 正式發布目標（明確指定中央庫，避免發布到預設本機路徑）
release_packages_path = "X:/rez-system/packages" if sys.platform == "win32" else "/mnt/x/rez-system/packages"

# ==============================================================================
# 2. 本機套件快取目錄 (Package Cache)
# 供 Render Farm 節點或工作站本機快取宣告了 cachable = True 的套件負載
# Linux 嚴禁使用重開機可能被清空的 /tmp，改用 /var/cache/rez
# ==============================================================================
cache_packages_path = "C:/rez-cache" if sys.platform == "win32" else "/var/cache/rez"

# ==============================================================================
# 3. Memcached 解析快取伺服器配置 (標準欄位)
# ==============================================================================
memcached_uri = ["192.168.0.221:11211"]

# 啟用解析結果快取
resolve_caching = True

# 啟用套件清單與檔案元數據快取
cache_package_files = True
cache_listdir = True

# 壓縮閥值（大於 1024 Bytes 的解析結果先壓縮後再進 memcached）
memcached_resolve_min_compress_len = 1024
```

> [!note] 解析逾時時間
> Rez 設定檔中並無 `resolve_timeout` 欄位。若需要在 CLI 或腳本中限制解析耗時，請使用 `rez-env --time-limit <SECONDS>` 參數。

## 六、設定驗證

在已配置好環境的機器上執行：

```bash
# 檢查單一設定欄位（rez-config 一次只接收一個欄位參數）
rez-config packages_path
rez-config release_packages_path

# 或列出所有生效的設定檔來源清單
rez-config --source-list

# 檢查 Memcached 伺服器狀態與快取命中統計
rez-memcache --stats
```
