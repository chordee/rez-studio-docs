# Rez 客戶端與算圖農場環境部署指南

本文檔定義藝術家 Windows 工作站與 Windows/Linux 算圖農場節點的本機環境建置標準、Local Package Cache 維護規範，以及跨平台算圖派送機制。

---

## 一、藝術家工作電腦（Artist Workstations）

藝術家電腦的配置原則為：**「開箱即用、背景透明、本機環境乾淨」**。

### 1. 本機目錄架構

所有 Rez 相關的客戶端檔案集中於使用者的個人家目錄：
* Windows 路徑：`%USERPROFILE%\rez-client`（即 `C:\Users\<username>\rez-client`）

```text
C:\Users\<username>\rez-client\
├── venv/                       # 【情境 A】Rez 執行核心（獨立 Python 虛擬環境）
│   ├── Scripts/rez/            # install.py 產生的隔離 CLI：rez.exe, rez-env.exe 等
│   └── Lib/site-packages/
└── packages/                   # 【情境 B】僅 TD 啟用的個人本機測試套件庫（選配）
```

### 2. 環境變數配置（全域 System / User Environment）

| 變數名稱 | 數值（Windows） | 說明 |
| :--- | :--- | :--- |
| `PATH` | `%USERPROFILE%\rez-client\venv\Scripts\rez;%PATH%` | 讓系統能執行由官方 `install.py` 隔離封裝的 Rez CLI |
| `REZ_CONFIG_FILE` | `X:\rez-system\config\rezconfig.py` | 強制讀取中央統一的配置規範 |

一般藝術家帳號不設定 `STUDIO_REZ_DEV`。只有 Pipeline TD 需要本機開發庫時，才設定 `STUDIO_REZ_DEV=1`。

### 3. 可重現客戶端安裝腳本 (`setup_client.ps1`)

> [!IMPORTANT]
> **官方安裝方式（install.py）的核心理由**
>
> Rez 官方強烈建議在生產環境使用官方倉庫提供的 `python ./install.py <DEST_DIR>` 進行部署。
> **真正的原因並非單純的套件相依，而是「執行期環境隔離」**：
> 若使用普通 pip 安裝至虛擬環境，當使用者在進入 `rez-env` 子 Shell 後，若載入的外掛（如 HtoA 或自研工具）修改了 `PYTHONPATH`，這些路徑會直接洩漏進同一個 Shell 中後續執行的 `rez` 指令本身的 Python 直譯器中，引發函式庫踩踏與 Crash。官方 `install.py` 會封裝出具備隔離直譯器與獨立 `sys.path` 的 CLI。
> 以下腳本固定下載 Rez 3.4.0 source archive，再呼叫官方 `install.py`。Python 僅接受 Rez 3.4.0 官方支援的 3.8 至 3.13；不會使用不受支援的更新版本。

```powershell
# setup_client.ps1 - Windows 工作站／農場 Rez 部署腳本 (相容 PowerShell 5.1 與 7+)
param(
    [string]$ClientDir = "$env:USERPROFILE\rez-client",
    [string]$RezRoot = "X:\rez-system",
    [ValidateSet("User", "Machine")]
    [string]$EnvironmentTarget = "User"
)

$ErrorActionPreference = "Stop"
$rezVersion = "3.4.0"

if (
    $EnvironmentTarget -eq "Machine" -and
    -not ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole(
        [Security.Principal.WindowsBuiltInRole]::Administrator
    )
) {
    throw "Machine 層級安裝需以系統管理員身分執行 PowerShell。"
}

# 1. 尋找 Rez 3.4.0 支援的 Python 3.8-3.13 實體直譯器
$pythonExe = $null
$pythonCandidates = @()

# 在 PS 5.1 中，外部命令向 stderr 輸出會觸發 NativeCommandError 終止錯誤
# 因此在探測 py.exe 時暫時允許 Continue 並檢查 $LASTEXITCODE
$prevEAP = $ErrorActionPreference
$ErrorActionPreference = "Continue"

$pyLauncher = Get-Command "py.exe" -ErrorAction SilentlyContinue
if ($pyLauncher) {
    foreach ($pythonVersion in @("3.13", "3.12", "3.11", "3.10", "3.9", "3.8")) {
        try {
            $result = (& $pyLauncher.Source "-$pythonVersion" -c "import sys; print(sys.executable)" 2>$null)
            if ($LASTEXITCODE -eq 0 -and $result) { $pythonCandidates += $result }
        } catch {}
    }
}
$ErrorActionPreference = $prevEAP

# 次選掃描系統路徑與常見安裝路徑（避開 WindowsApps 空殼捷徑）
$found = Get-Command "python.exe" -CommandType Application -ErrorAction SilentlyContinue |
    Where-Object { $_.Source -notlike "*WindowsApps*" } |
    Select-Object -First 1
if ($found) { $pythonCandidates += $found.Source }

$pythonCandidates += @(
    "C:\Python313\python.exe", "C:\Python312\python.exe", "C:\Python311\python.exe",
    "C:\Python310\python.exe", "C:\Python39\python.exe", "C:\Python38\python.exe"
)

foreach ($candidate in ($pythonCandidates | Select-Object -Unique)) {
    if (-not (Test-Path -LiteralPath $candidate)) { continue }
    try {
        $versionText = & $candidate -c "import sys; print(f'{sys.version_info.major}.{sys.version_info.minor}')"
        if ($LASTEXITCODE -ne 0 -or -not $versionText) { continue }
        $version = [version]$versionText
    } catch { continue }
    if ($version -ge [version]"3.8" -and $version -lt [version]"3.14") {
        $pythonExe = $candidate
        break
    }
}

if (-not $pythonExe) {
    throw "錯誤：找不到 Rez 3.4.0 支援的 Python 3.8-3.13 實體執行檔。"
}

Write-Host ">>> 使用 Python 直譯器: $pythonExe"

# 2. 定義目錄結構
$installDir = "$ClientDir\venv"
$rezBinDir = "$installDir\Scripts\rez"
$rezExe = "$rezBinDir\rez.exe"

New-Item -ItemType Directory -Force -Path $ClientDir | Out-Null

# 3. 下載鎖定版本 source archive，使用官方 install.py 建立 production install
if (-not (Test-Path -LiteralPath $rezExe)) {
    if (Test-Path -LiteralPath $installDir) {
        throw "錯誤：$installDir 已存在但不是完整的 Rez production install；請先備份後移除，再重新執行。"
    }

    $tempDir = Join-Path ([System.IO.Path]::GetTempPath()) ("rez-install-" + [guid]::NewGuid())
    $archivePath = Join-Path $tempDir "rez-$rezVersion.zip"
    $sourceDir = Join-Path $tempDir "rez-$rezVersion"
    $nasArchivePath = Join-Path $RezRoot "installers\rez-$rezVersion.zip"
    New-Item -ItemType Directory -Path $tempDir | Out-Null

    try {
        $copiedFromNas = $false
        if (Test-Path -LiteralPath $nasArchivePath) {
            try {
                Copy-Item -LiteralPath $nasArchivePath -Destination $archivePath
                $copiedFromNas = $true
            } catch {
                Write-Warning "無法讀取 NAS 安裝包，改從 GitHub 下載：$($_.Exception.Message)"
            }
        }

        if (-not $copiedFromNas) {
            [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
            $sourceUrl = "https://github.com/AcademySoftwareFoundation/rez/archive/refs/tags/$rezVersion.zip"
            Invoke-WebRequest -UseBasicParsing -Uri $sourceUrl -OutFile $archivePath
        }

        Expand-Archive -LiteralPath $archivePath -DestinationPath $tempDir
        & $pythonExe "$sourceDir\install.py" -v $installDir
        if ($LASTEXITCODE -ne 0) { throw "Rez install.py 執行失敗，exit code: $LASTEXITCODE" }
    }
    finally {
        Remove-Item -LiteralPath $tempDir -Recurse -Force -ErrorAction SilentlyContinue
    }
}

if (-not (Test-Path -LiteralPath $rezExe)) {
    throw "錯誤：install.py 完成後找不到 $rezExe"
}

# 4. 配置環境變數
$rezConfigPath = Join-Path $RezRoot "config\rezconfig.py"
$rezRootForConfig = $RezRoot.Replace("\", "/").TrimEnd("/")

# 直接讀寫 registry，保留 Path 中尚未展開的 %VAR% 與 REG_EXPAND_SZ 類型
$envKey = if ($EnvironmentTarget -eq "Machine") {
    [Microsoft.Win32.Registry]::LocalMachine.OpenSubKey(
        "SYSTEM\CurrentControlSet\Control\Session Manager\Environment", $true
    )
} else {
    [Microsoft.Win32.Registry]::CurrentUser.OpenSubKey("Environment", $true)
}

try {
    $rawPath = [string]$envKey.GetValue(
        "Path", "", [Microsoft.Win32.RegistryValueOptions]::DoNotExpandEnvironmentNames
    )
    $pathEntries = @($rawPath -split ";" | Where-Object { $_ })
    if ($pathEntries -notcontains $rezBinDir) {
        $newPath = (@($rezBinDir) + $pathEntries) -join ";"
        $envKey.SetValue("Path", $newPath, [Microsoft.Win32.RegistryValueKind]::ExpandString)
    }
} finally {
    $envKey.Close()
}

[Environment]::SetEnvironmentVariable("REZ_CONFIG_FILE", $rezConfigPath, $EnvironmentTarget)
[Environment]::SetEnvironmentVariable("STUDIO_REZ_ROOT", $rezRootForConfig, $EnvironmentTarget)

# 5. Smoke Test (冒煙測試：使用 rez --version)
Write-Host ">>> 執行 Rez 安裝驗證..."
$installedVer = & $rezExe --version
Write-Host ">>> 驗證成功！目前 Rez 版本: $installedVer"
```

不帶參數時，腳本維持工作站行為：安裝至 `%USERPROFILE%\rez-client`，並寫入 User 層級環境變數。Windows 農場節點則由系統管理員在提升權限的 PowerShell 中執行：

```powershell
.\setup_client.ps1 `
    -ClientDir "C:\rez-client" `
    -RezRoot "\\nas\share\rez-system" `
    -EnvironmentTarget "Machine"
```

Pipeline TD 若需要情境 B，再另外執行：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\rez-client\packages" | Out-Null
[Environment]::SetEnvironmentVariable("STUDIO_REZ_DEV", "1", "User")
```

設定後須開啟新終端機。一般藝術家帳號不得設定此變數，也不建立 `packages` 目錄。

## 二、算圖農場節點（Render Farm Hosts）

### 1. 農場節點配置標準

| 作業系統 | Rez 核心路徑（情境 A） | 本機快取目錄（Local Cache） | 必設環境變數 |
| :--- | :--- | :--- | :--- |
| **Windows Farm** | `C:\rez-client\venv\Scripts\rez` | `C:\rez-cache` | Machine 層級：<br>`REZ_CONFIG_FILE=\\nas\share\rez-system\config\rezconfig.py`<br>`STUDIO_REZ_ROOT=//nas/share/rez-system`<br>`REZ_DISABLE_HOME_CONFIG=1`<br>`STUDIO_FARM_NODE=1` |
| **Linux Farm** | `/opt/rez-client/venv/bin/rez` | `/var/cache/rez` | systemd unit：<br>`REZ_CONFIG_FILE=/mnt/x/rez-system/config/rezconfig.py`<br>`STUDIO_REZ_ROOT=/mnt/x/rez-system`<br>`REZ_DISABLE_HOME_CONFIG=1`<br>`STUDIO_FARM_NODE=1` |

Windows Deadline Worker 通常以 service 帳號執行，無法依賴互動使用者的 User 層級環境變數。上述農場安裝命令已將 `PATH`、`REZ_CONFIG_FILE` 與 `STUDIO_REZ_ROOT` 寫入 Machine 層級；另外設定農場專用變數：

```powershell
[Environment]::SetEnvironmentVariable("REZ_DISABLE_HOME_CONFIG", "1", "Machine")
[Environment]::SetEnvironmentVariable("STUDIO_FARM_NODE", "1", "Machine")
```

Machine 層級環境變數只會在 service 啟動時讀取。完成設定後，必須重啟 Deadline Launcher／Worker service；若無法個別重啟，則重開機。範例中的 `\\nas\share` 必須換成實際 NAS UNC 路徑。

Linux Deadline 若由 systemd 啟動，不會讀取 `/etc/profile` 或 `~/.bashrc`。請在實際 Deadline unit 的 override 中使用 `Environment=`：

```ini
[Unit]
RequiresMountsFor=/mnt/x

[Service]
Environment="REZ_CONFIG_FILE=/mnt/x/rez-system/config/rezconfig.py"
Environment="STUDIO_REZ_ROOT=/mnt/x/rez-system"
Environment="REZ_DISABLE_HOME_CONFIG=1"
Environment="STUDIO_FARM_NODE=1"
Environment="PATH=/opt/rez-client/venv/bin/rez:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
```

`Environment="PATH=..."` 會整個取代 systemd 預設的 `PATH`，因此必須連同系統目錄一起列出；Rez 安裝方式見 [00-Rez安裝與導入順序](00-Rez安裝與導入順序.md)。

也可改用 `EnvironmentFile=` 指向受控的農場環境檔。修改 unit 後執行 `systemctl daemon-reload`，再重啟實際的 Deadline Launcher／Worker unit。

> [!IMPORTANT]
> **嚴格隔離本機配置與開發庫**
>
> 1. **全域與家目錄設定阻絕**：算圖農場必須設定 `REZ_DISABLE_HOME_CONFIG=1` 避免讀取家目錄下可能存在的 `.rezconfig`。
> 2. **本機套件庫隔離**：農場帳號不得設定 `STUDIO_REZ_DEV`，且算圖任務呼叫 `rez-env` 時固定帶上 `--no-local`，以兩層防護切斷本機開發庫。
> 3. **DCC 偏好設定受控導向**：宣告 `STUDIO_FARM_NODE=1` 可讓 DCC Wrapper（如 [04-Houdini-Wrapper-套件實作](04-Houdini-Wrapper-套件實作.md)）透過 `defined("STUDIO_FARM_NODE")` 偵測到當前為農場執行環境，將 `HOUDINI_USER_PREF_DIR` 等偏好目錄切換至獨立受控的暫存區，徹底阻絕使用者本機外掛滲漏，同時完全不影響美術機台。

### 2. Local Package Cache 的真實行為與維護

在 `rezconfig.py` 中設定 `cache_packages_path` 並不代表所有套件都會自動複製：

1. **套件需顯式支援快取**：
   Rez 預設 `default_cachable = False`。只有在套件的 `package.py` 中顯式宣告 `cachable = True`（且確保二進位路徑具備 `relocatable = True` 條件）的 Payload 套件，才會被複製到快取目錄。Wrapper 套件絕不可設為 cachable。
2. **非同步複製行為**：
   Rez 的快取預設採用非同步下載。第一次在該節點執行該套件時，工作進程會先直接從 NAS 讀取檔案，背景進程同時進行複製；待快取寫入完畢後，後續的任務才會完全命中本機 SSD。
3. **快取預熱與維護指令**：
   - Linux 農場嚴禁使用 `/tmp`（避免重開機時快取遺失觸發冷啟動風暴），改用專屬硬碟分區如 `/var/cache/rez`。
   - 使用 `rez-pkg-cache` 工具進行快取狀態監控與清理：
     ```bash
     # 檢視快取狀態（不帶參數即為列出當前快取狀態）
     rez-pkg-cache
     
     # 在大檔期開工前手動預熱指定套件 (使用 --pkg-cache-mode sync 同步拉取至本地)
     # Linux:
     rez-env htoa-6.3.3.0 --pkg-cache-mode sync -- true
     # Windows:
     rez-env htoa-6.3.3.0 --pkg-cache-mode sync -- cmd /c exit 0
     
     # 清理超過容量上限或過期的舊套件快取
     rez-pkg-cache --clean
     ```

## 三、算圖派送與跨平台 Context 處理架構

> [!CAUTION]
> **跨平台陷阱：Windows `.rxt` 無法直接在 Linux 上還原**
>
> `.rxt`（Resolved Context）檔案儲存的是**已經完成解析的具體 Variant 實體控制代碼（Handle）**。如果在 Windows 上解析，裡面凍結的就是 `platform-windows` 變體。直接把 Windows 的 `.rxt` 丟到 Linux 農場執行，系統不會自動改抓 Linux 版的外掛，而是會因為找不到 Windows DLL 而崩潰。

### 正確的跨平台算圖派送架構

```
[ 工作站 (Windows) ]
    │
    ├─ 1. 藝術家提交算圖任務
    ├─ 2. 提交器 (Submitter) 抓取當前工作環境的「套件請求清單」與「時間戳鎖 (Timestamp Lock)」
    │     例如: "houdini-20.5.278", "htoa-6.3.3.0", "studio_pipeline-1.2.0"
    │
    ▼ (透過 Deadline / OpenCue / Tractor 等派遣系統派送任務)
    │
[ 派遣系統 / 目標農場節點 ]
    │
    ├─ 3. 專案資產路徑轉譯 (Path Mapping): 由農場適配器處理 (X:/proj -> /mnt/x/proj)
    │
    ├─ 4. 在目標平台上生成該平台專屬的 .rxt 環境 (或由 Dispatcher 預先解析好):
    │     rez-env houdini-20.5.278 htoa-6.3.3.0 studio_pipeline-1.2.0 --no-local -o /mnt/x/jobs/1024/linux_env.rxt
    │
    └─ 5. 算圖節點載入專屬 Context 並執行算圖:
          rez-env -i /mnt/x/jobs/1024/linux_env.rxt -- hython /mnt/x/jobs/1024/render.py
```

### RXT 標準指令總結

| 操作 | 官方正確指令 | 錯誤示範（切勿使用） |
| :--- | :--- | :--- |
| **解析並產生 Context** | `rez-env <requests> -o <path.rxt>` | `rez-context --output <path.rxt>`（`rez-context` 僅供檢視） |
| **載入 Context 並執行** | `rez-env -i <path.rxt> -- <cmd>` | `rez-env -R <path.rxt>`（無此參數） |
| **檢視已儲存的 Context** | `rez-context <path.rxt>` | — |
